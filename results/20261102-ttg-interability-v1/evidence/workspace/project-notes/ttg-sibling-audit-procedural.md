# Static sibling-access audit: TPC-C and Wikipedia

Source-only audit of all 5 TPC-C and 5 Wikipedia selected operation identities. No DB/compiler/tests or benchmark edits. No native acceptance or performance claim.

Sibling access interference means one queued activation can modify state/graph/control that changes another queued activation future DB access or cancellation. Ordinary loop/transaction dependence is reported separately. Output-only shared state still retains native output semantics.

| Operation | OSP sibling category | Actual dependency | Required analysis / boundary |
|---|---|---|---|
| tpcc/NewOrder | no_visit_sibling_dispatch | Single Root ability. Repeated item/stock input IDs can alias the same Stock: quantity read-modify-write and replenishment branch form loop-carried dependence; exceptions must roll back preceding writes. District order-ID update precedes Order insertion. | The absence of visit dispatch is syntactic. A may-alias storage-effect summary detects the sequential Stock effect; no unconditional distinct-stock proof is justified from arbitrary input lines. Read-only target discovery may be isolated from transactional mutations; do not delete validation/replenishment or replace rollback with validate-first and call it equivalent. |
| tpcc/Payment | no_visit_sibling_dispatch | Single Root ability; input branch selects ID or name/median customer; balance/credit/history updates and timestamp call have visible effects. | Control/data dependencies are explicit; transaction effects require memory/storage summaries. Separate customer lookup from mutations; business validation and credit semantics stay. |
| tpcc/OrderStatus | no_visit_sibling_dispatch | Single Root ability; customer selection and sorted order selection determine subsequent OrderLine read. No persisted mutations. | Read-comprehension, sorting/selection, and may-raise summaries expose dependent relational reads. A relational selection/join region is possible in principle; no OSP sibling proof or implemented SQL support is claimed. |
| tpcc/Delivery | no_visit_sibling_dispatch | Single Root ability loops over districts; queries minimum pending Order, changes new_order/carrier/lines/customer totals. Under arbitrary shared topology an earlier write may affect another district iteration. | Need may-alias graph/storage effects or declared district ownership/uniqueness invariant for loop independence. Preserve oldest-order selection, mutation order, owner checks and rollback; no guard removal recommended. |
| tpcc/StockLevel | no_visit_sibling_dispatch | Single Root ability. Recent-order line scan builds item_ids used in a later stock membership filter. Output deduplication/reduction, no persistence writes. | The data dependence is visible through the dictionary membership summary. Relational semijoin/distinct lowering can represent this phase dependence; not a sibling-dispatch issue. |
| wikipedia/GetPageAnonymous | provable_no_sibling_access_interference | Every visit schedules exactly one selected object: pages[0], revisions[0], texts[0]. page_id/latest_id/text_id are parent-to-child query parameters. Eligible parameterized lookup chains can be considered for lowering; result/error semantics remain native unless supported. |
| wikipedia/GetPageAuthenticated | provable_no_sibling_access_interference | Same singleton Page/Revision/Text chain; user/group/block checks precede visits, outputs use selected user text. | Same singleton and read summary; user validation/exception is a control boundary, not sibling mutation. No simplification required; retain user validation, group and block behavior. |
| wikipedia/AddWatchList | no_visit_sibling_dispatch | Single Root ability loops main/talk namespaces; duplicate checks, insertion, and user timestamp updates; duplicate second operation may roll back first. | Loop/effect/exception summaries expose transaction dependencies; namespaces are explicitly distinct but this does not remove rollback semantics. Do not delete duplicate guards or change partial-write rollback test. |
| wikipedia/RemoveWatchList | no_visit_sibling_dispatch | Single Root ability; scoped Watch lookup/destruction and user timestamp. remove_node calls Jac.destroy. | Interprocedural summary for the available remove_node helper marks storage deletion; _now is an external time input. Read target regions may be separate; deletion/timestamp are business effects. |
| wikipedia/UpdatePage | no_visit_sibling_dispatch | Single Root ability; ID maxima, inserts, revision/page links, latest revision updates, watcher reads and notification updates, log/user writes. | Ordinary value and storage dependencies are explicit; need transactional ordering and ID allocation assumptions, not a sibling queue model. Full update lowering requires transaction/effect semantics. No semantics-preserving deletion of these operations proposed. |

Counts: 2 singleton-chain readers with no sibling access interference; 8 operations have no visit-based sibling dispatch, with ordinary procedural and transaction dependencies retained. No program simplification is needed to determine those categories. A claim that the whole operation can be lowered is a separate question.
