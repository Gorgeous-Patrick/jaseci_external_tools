# Domain-A sibling future-access source audit

Inspected 13 registered readers from the frozen 30-entry registry. All 13 admit an absence proof under the closed-world assumptions below; none is classified MAY or unknown at the registered-reader level. These are source arguments, not results from an implemented static analyzer. Other apps and the 61 paper cases are audited separately.

Shared output state is distinct from state controlling later graph access. NO means no sibling write reaches a later access decision; it does not imply output commutativity, safe reordering, or independent business operations. MAY exposes a concrete dependence path; unknown means a missing proof, not theoretical impossibility.

## Additional walkers: preserve the scope of the dependence

- **issue_desk / ReachIssue, BlockIssue — STATIC_MAY_DEPENDENCE (same_walker_queue_and_nested_walker).** ReachIssue.seen guards return before Blocks visit; found triggers disengage. Diamond A->B,C; B->D,C->D makes the second D entry return after the first inserts D. If B matches target, queued C can be cancelled. This is queue/identity dependence, not a depth argument. BlockIssue uses reach.found to suppress a new Blocks edge; exact absence needs topology/identity and target reasoning. Source: ReachIssue,BlockIssue: 198–247.
- **approval_desk / SubmitExpense — STATIC_MAY_DEPENDENCE (sibling_reduction_to_ancestor_exit).** LineItem siblings add quantity*unit_cents to self.total. Expense exit tests zero and >50000, then selects manager versus manager+finance approver queries and creates steps. Contributions 49999 and 2 change the exit finance path. No LineItem entry branches on prior total; the dependence is on the later common exit. A pure reduction summary can expose it without changing semantics. Source: SubmitExpense: 164–210.
- **stock_room / ReserveStock — STATIC_MAY_DEPENDENCE (ordinary_loop_not_queued_siblings).** remaining controls break and allocation/write targets in the lot loop. Quantity 3 with available lots [3,3] touches only the first; availability [2,3] also allocates from the second. Preserve sequential remaining and FIFO ordering; flattening this loop as independent siblings would change semantics. Source: ReserveStock: 189–236.
- **stock_room / ReleaseReservation, DispatchReservation — PROVABLE_NO_FUTURE_ACCESS_DEPENDENCE_WITHIN_THIS_TRAVERSAL (actual_sibling_writes_but_no_access_feedback).** Allocation siblings query their own FromLot, then update Lot.available or Lot.dispatched. Later Allocation target selection does not read either updated field, even if two allocations alias a lot. Writes may conflict and final values matter; shared writes alone do not establish future-access dependence. Reservation exit writes status and reports; report view reads graph fields after the updates. Source: ReleaseReservation,DispatchReservation: 239–304,59–80.
- **help_queue / EvaluateSLA, _escalate — STATIC_MAY_DEPENDENCE_WITHOUT_CARDINALITY_INVARIANT (conditional_same_walker_parent_state_and_heap_effects).** SupportDesk entries overwrite self.now; Ticket entries use it to decide whether to query the senior agent and rewrite assignment. With FIFO pending D1,D2, ticks 0/100, D1 ticket opened0 and SLA30, D2 executes before the D1 ticket and changes its escalation decision. On the seeded/application-generated single-desk graph (Seed 89-108, no business desk constructor), now is stable across distinct Ticket siblings. _escalate changes AssignedAgent edges/escalated, not status, replies or SLA read by the next distinct Ticket guard; prove nonaliasing if treating these writes as independent. This conditional proof is not a blanket unknown or a claim that the two-desk state is produced by Seed. Source: EvaluateSLA,_escalate: 229–253,52–60,86–108.
- **recipe_pantry / ShoppingList — PROVABLE_NO_FUTURE_ACCESS_SIBLING_DEPENDENCE (shared_reduction_used_only_in_output).** required is a shared keyed sum, but no meal access is selected from it. _requirements reads only the current Meal/Recipe graph. Root exit always queries all Ingredients; required changes report values/shortages, not query targets or branches before that query. Source: ShoppingList: 134–156,33–38.
- **issue_desk / CloseIssue, ReopenIssue — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** Closing a blocker changes the open-blocker guard on a later dependent CloseIssue. These single-Root operations have interoperation heap dependence, not queued Issue sibling callbacks. Source: CloseIssue,ReopenIssue: 249–299.
- **approval_desk / DecideApproval, PayExpense — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** Deciding an earlier step changes the earlier-position pending guard for a later decision; approval/payment status and HasPayment control PayExpense. Root-only calls, not sibling visits. Source: DecideApproval,PayExpense: 212–276.
- **stock_room / ReserveStock, ReceiveStock, ReleaseReservation, DispatchReservation — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** Reserving the last available unit changes another reservation availability guard. Receive/release change available; dispatch/release change reservation status guards. Separate calls/heap conflicts; ReserveStock loop and allocation siblings are classified separately above. Source: ReserveStock,ReceiveStock,ReleaseReservation,DispatchReservation: 166–304.
- **clinic_queue / BookAppointment, CancelAppointment, AddSlot — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** A booked slot creates HasAppointment; a second overlapping slot for the same practitioner now returns before creation. Cancellation removes that booked-status condition. All are Root-only. Source: BookAppointment,CancelAppointment,AddSlot: 112–211.
- **course_path / CompleteLesson, Enroll, AddLesson — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** Completing prerequisite P adds Completion/ForLesson, changing a later dependent lesson guard. Duplicate enrollment and prerequisite topology also affect Root-only calls. No recursive prerequisite walk or chain proof is implemented here. Source: CompleteLesson,Enroll,AddLesson: 134–266,35–57.
- **library_loans / BorrowTitle, PlaceHold, CancelHold, ReturnLoan, _lend — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** Borrowing the last copy changes later availability/hold guards. Returning marks a loan/copy, selects the lowest-position queued hold, follows RequestedBy and calls _lend; cancelling a hold changes that selected patron. All business walkers have one Root handler. Source: BorrowTitle,PlaceHold,CancelHold,ReturnLoan,_lend: 176–306,54–72.
- **event_seats / HoldSeats, ConfirmBooking, CancelBooking — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** Holding seat S changes S.status, causing another hold of S to return before booking writes; cancellation frees seats and confirmed cancellation selects a refund write. Root-only loops, not Seat entry siblings. Source: HoldSeats,ConfirmBooking,CancelBooking: 141–237,44–69.
- **help_queue / AdvanceClock, ReplyTicket, AssignTicket, ResolveTicket — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** AdvanceClock changes deadline comparisons; first ReplyTicket changes HasReply and may escalate; escalation changes later agent-tier guard. ResolveTicket uses status+reply guards. These are cross-call heap effects; EvaluateSLA is separately classified. Source: AdvanceClock,ReplyTicket,AssignTicket,ResolveTicket: 183–305,52–60.
- **recipe_pantry / BuyIngredient, CookMeal — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** Cooking one of two meals that share the last ingredient unit decreases units and causes the second cook to return before consumption writes. Root-only operations; the quantity check and ordered mutation loop must be preserved. Source: BuyIngredient,CookMeal: 158–203,33–38.
- **trip_board / ReserveStay, CancelStay, AddStop, MoveStop — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** A stay consuming remaining capacity changes the next ReserveStay guard; cancellation restores capacity. Stop insertion/move reads and rewrites sibling position fields in an ordinary loop. There are no queued Stop callbacks in these business walkers. Source: ReserveStay,CancelStay,AddStop,MoveStop: 80–203.
- **delivery_route / AssignParcel, LoadRoute, DeliveryAttempt, RetryStop — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** A successful attempt marks the earliest stop delivered, so the next attempt selects a different stop/parcel; failure blocks progress until retry. Assignment changes capacity/status guards. Root-only calls and local loops, not queued Stop abilities. Source: AssignParcel,LoadRoute,DeliveryAttempt,RetryStop: 130–252.
- **hiring_pipeline / OfferApplication, ApplyJob, ScheduleInterview, ScoreInterview — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** Two eligible applications for a one-position job: offering the first changes the offered-count guard and blocks the second; offering the same candidate elsewhere also changes exclusivity. Root-only calls, not Application siblings in HiringBoard. Source: OfferApplication,ApplyJob,ScheduleInterview,ScoreInterview: 106–227.
- **sales_pipeline / AcceptQuote, CloseWon, QualifyOpportunity, LogActivity — STATIC_MAY_DEPENDENCE_ACROSS_CALLS (interoperation_heap_dependence_not_same_walker_siblings).** Accepting quote Q1 sets accepted and makes Q2 on the same Opportunity return; CloseWon writes stage and amount after querying accepted quotes. Root-only calls. SalesBoard.won_cents remains output-only. Source: AcceptQuote,CloseWon,QualifyOpportunity,LogActivity: 115–236.

## Proof boundaries

The model is the closed-world ordinary Jac application, standard graph operations and stable identity; reader helpers were followed. There are no observed opaque external reader callbacks. Arbitrary external effects, field descriptors, callback overrides, concurrent writes or output-to-graph aliasing require new summaries or an unknown result. No universal decidability theorem or automatic analyzer implementation is claimed.

The `EvaluateSLA` multi-desk witness is conditional on allowing multiple desks. Its Seed creates one desk and returns if one exists; the business code has no second desk constructor. An invariant proof over that reachable state can eliminate the clock-overwrite witness. Distinct-ticket ownership/nonaliasing must also be proved before discarding its assignment writes.

A visited counter is a TOTAL activation count, never automatically depth. None of these reader arguments treats relation names as singleton/acyclic guarantees. Fanout, convergence and duplicate scheduling remain possible; exact graph-dependent scheduling and `ReachIssue` cancellation require identity/topology reasoning.

No tests, DB sessions, compiler invocations, performance measurements or SQL claims were used. Existing audit files and frozen suites were left unchanged.
