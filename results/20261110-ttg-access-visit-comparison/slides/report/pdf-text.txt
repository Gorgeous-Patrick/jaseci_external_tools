Current implementation gap: unresolved origin ends the executable prefix




      Ability entry hook                                           Origin becomes known               Ordinary helper
      Compile/select Access prefix                                 Native jobj returns Meal           _requirements(meal)
      meal = jobj(self.meal_id)                                    No new Access checkpoint           Normal demand reads




      Meal → Recipe → Requirement → Ingredient

 CookMeal has no later explicit graph query after this helper
     It checks stock and writes inventory / Consumption edges. The queries are inside the helper.


PlanMeal / CookMeal / BuyIngredient have no later prefetch submissions in these captures.
A later ability entry can trigger prefetch, but an ordinary helper call is not a new ability entry.

What to improve next
Recover useful coverage without replacing selective analysis with broad traversal



 1 Model direct identity lookup as an Access origin
     jobj(id) → object identity → typed subsequent graph paths.



 2 Resume after the last unresolved dependency
     Insert a checkpoint after meal becomes known; preserve effects and native execution order.



 3 Extend the necessity audit
     Separate payload, predicate columns and identity-only reads; keep root/entry demands visible.



 4 Re-test both objectives
     Report useful coverage and confirmed unnecessary fetches together; keep slow/unsupported cases.
