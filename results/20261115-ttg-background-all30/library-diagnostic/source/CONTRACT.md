# LibraryLoans exact-key availability diagnostic

Observation only on frozen restored runtime 93ea / commit5cb1. No production edits, waits, SQL/condition/key precomputation, hook movement or tuning. Install `library_timeliness.install(output_dir)` after the unchanged compact/background observers. It returns an observer; `validate_trace(paths)` is a small stdlib-only completeness check before acceptance. Header receipt is written at install, including Off. Buffered events flush after the existing POST-HTTP drain; it calls that original drain unchanged. Trace files are `library-timeliness-<pid>.jsonl` and must be sealed with all other case files.

For each traced workflow use `validate_trace(paths, require_activity=True)`; the traced Off case also uses `require_access_sql=True`. This checks actual logical Access and nested cache activity, and actual SQL joins in Off, rather than header presence alone. Jac separate implementation globals are rebound only where the exact original seam identity matches; no detached aliases are assumed routed. Legitimate zero prefetch/empty cache is allowed.

Native `_sql_pairs` is one logical path resolution. The emitted-key and ordinary-key cache attempts are nested, not two Access misses. `resolve_query_count` is also bracketed; nested resolution retains one logical ID. This denominator is instrumented native resolver invocations, not every source-language Access expression. Caller source positions and `from_visit`/operation context must not be assumed from a SQL fingerprint. Exact actual keys use a typed full-key table; SQL origin/filter/actor operands remain part of identity. Session and retained cache-dictionary identities define an epoch. No speculative call constructs keys.

Class-bearing emitted shapes use per-process interned class tokens with strong references preventing identity reuse. Module/qualname are display only; distinct classes with identical names remain distinct. Builtin type storage descriptors bypass custom metaclass getters. These tokens are process-local; comparisons always include PID and never equate a token across processes.

Actual cache writes are distinguished by the original native drain caller frame's `record.job_id`, native Access, or other observed source; valid empty tuples and count zero are hits when the original return is not None. A hit is attributed to a recorded write only when the returned object is the exact stored object. Cache content availability is not business necessity.

Hook/job submission captures the actual immutable job and owner Session/epoch/actor/snapshot. Existing completed phase means earlier result-ready, finished means cleanup observation, wrapper return exposes only actually materialized output keys, and Future.done is observed before and after each exact lookup without waiting. False→true brackets readiness at the boundary and is unknown, not ready-before. The done callback is an observation after Future state changes, not an exact transition clock. Owner publication records actual stored entries, not an inferred counter. Coverage can be classified retrospectively only for exact keys actually materialized; cancelled-before-materialization jobs have unknown coverage, not proven uncovered/late.

Lease cancellation, owner close and epoch/snapshot mismatch are separate from insufficient lead time. Worker result-ready alone does not prove Future-ready/publishable. A proved ready-before yet unpublished exact key with valid lease differs from pending exact-key work. Native hits may come from a prior native query, not prefetch. Aliases stay explicit and distinct; attempts in the same logical Access are linked without inventing equivalent keys.

Payload operations are separate: get/batch_get bracketed without double-counting nested calls, actual raw publication/promotion and load_full observed, no prefetch-service claim from path hits. Direct `_run` events link actual native SQL to Access/payload/job context, without iterating returned generators or adding SQL.

All event buffering, key encoding/hash, frame inspection, Future state checks and clocks perturb timing. This is a separate diagnostic (three restored traced repeats, Off traced and restored untraced controls), not new primary n5 performance or an experiment relocating a hook. Gross n1 tracing overhead cannot isolate per-event overhead. No causal hook-placement claim follows solely from late or missing cache availability.
